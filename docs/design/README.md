# docs/design/

**Purpose:** Subsystem design documents — how a subsystem is built, once its architecture is decided.

**Contains:** One document per subsystem, each covering purpose, architecture, interfaces, extension points, limitations, and future work (BOOTSTRAP.md section 12).

**Does not contain:** Proposals under debate (those are RFCs) or decision records (those are ADRs).

**Governing rule:** Section 5 of every design document — limitations — is mandatory. A document claiming no limitations is incomplete, not exemplary.
