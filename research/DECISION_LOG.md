# Research decision log

Why things are the way they are, so the project doesn't depend on anyone's memory of it. Newest first. Add an entry whenever a research decision is made — a baseline chosen, a metric changed, a hypothesis rejected, a branch merged or archived — not just when something goes wrong.

---

**Restructured governance docs from `docs/rfc/RFC-0001-*.md` (a numbered-RFC/ADR scheme) to a flat `research/` directory (`GIT_WORKFLOW.md`, `DECISION_LOG.md`, `SPEC_TEMPLATE.md`, `AUDIT_METHODOLOGY.md`).**
Explicit naming-convention preference, matching the convention already adopted in a sibling project. The RFC's content and section numbering (§1–§11) are unchanged, only the file's location and its bureaucratic front-matter (`Number: RFC-0001`, `Status: Draft`, a link to an `ADR-0001` that was never actually written) were dropped. That dangling ADR link was caught and fixed while moving the file, not left in place — the advisory-vs-mandatory question it pointed at is still genuinely unresolved (`AUDIT_METHODOLOGY.md` §10), and the moved document says so explicitly rather than implying a decision exists.

**Adopted the research-branch workflow in `GIT_WORKFLOW.md`.**
Prior work (the audit mechanism itself, the physics-to-NAS pivot, the archive of the old direction) was all done directly on `main`, without a formal spec-first branch process — main was still the only branch worth having at that point, since nothing was substantial enough yet to need isolating. That work is real and stays in the historical record as-is; this decision is about *future* branches, starting with whatever implements `plugins/nas_search/`, not a retroactive relabeling of what already happened.

**Renamed the repository `scientific-discovery-engine` → `Null-Scaffold-Audit`; retired "SDE" as the project's branding.**
SDE's identity — "orchestrates load → split → fit → predict → validate → score, delegating scientific content to a plugin" — doesn't describe what this project is now about. The audit mechanism doesn't go through that pipeline shape at all; `engine/audit/` has its own separate interfaces (`BaseSearcher`/`Scaffold`/`AuditProblem`) specifically because they were built to know nothing about loading a dataset and scoring a model. The only thing genuinely reused from the SDE apparatus is the plugin registry as a name-to-factory lookup, not the "scientific discovery" framing. "Null-Scaffold-Audit" is not a new coinage — it's the term `AUDIT_METHODOLOGY.md`, `engine/audit/`, and its own docstrings already used for this mechanism, just finally put in the title. The Python package name and `sde` CLI command were deliberately *not* renamed alongside — a more disruptive, purely mechanical change with no clear ask behind it, kept out of scope.

**Chose "Does the Scaffold Earn Its Keep" as the study name over "No Free Search."**
"No Free Search" was rejected on inspection: it puns on the No Free Lunch theorem, but NFL is a specific, different, theoretical claim (averaged over *all possible* objective functions, no algorithm beats another — a uniform-distribution average-case result) from what this project actually tests (does *this* NAS controller beat *this* budget-matched random search, on real non-uniform benchmark distributions). Using the pun risked implying a claim the research doesn't make. "Does the Scaffold Earn Its Keep" was chosen instead because it matches the citation genre this project already leans on — Dacrema et al.'s "Are We Really Making Much Progress?", Musgrave et al.'s "A Metric Learning Reality Check" — colloquial-but-precise question titles, not a pun requiring an asterisk.

**Pivoted the research direction from physics equation discovery to auditing NAS controllers against budget-matched random search.**
The physics direction's own audit (`archive/physics_equation_discovery/results/null_scaffold_audit/summary.csv`) found its scaffold statistically indistinguishable from — or worse than — plain restarts on nearly every problem, and it sits below current symbolic-regression SOTA (QDSR: 91.6% exact recovery on Feynman vs. this project's 0/8 shown matches). Three independent adversarial literature searches additionally found the field already treats raw Feynman-rediscovery as a contaminated, non-claimable result (this is LLM-SRBench's own stated motivation for existing). The audit *mechanism* that caught the physics scaffold's degeneracy had no confirmed identical prior art in the same searches — ScaffoldSafety (arXiv:2603.10044) is the closest match and lacks the budget-matched-restart control this project's design centers on. Full comparison across four candidate pivot directions (generalize the audit broadly, audit LLM-agent scaffolds on GAIA, a narrower oracle-ceiling-only extension, or build a real climate-science domain) is in this conversation's history; NAS-via-NATS-Bench won on being simultaneously zero-cost (no GPU training, tabular lookup only), scoped correctly for the available budget, and pointed at a citably still-open question (Li & Talwalkar 2019, contested as recently as 2023–2025 follow-ups).

**Archived, not deleted, the physics/synthetic direction (`archive/physics_equation_discovery/`).**
It's the provenance for the one verified finding this project has produced: the archived scaffold's three "refine" iterations were, for a documented stretch of development, character-identical — a fixed random seed meant the loop never actually looped, and nothing in the pipeline noticed until the audit was built. Deleting that code would have destroyed the evidence trail for why `engine/audit/` exists at all. Everything under `algorithms/`, `validators/`, `engine/{expressions,scoring.py,evaluation}/`, and all of `results/` moved with it, since they're only meaningful in service of the archived direction. `engine/audit/` and the rest of `engine/`'s plugin/registry/discovery/orchestrator apparatus stayed active — domain-agnostic, reused as-is by whatever comes next.

**Chose NATS-Bench over the (deprecated) NAS-Bench-201 as the benchmark table.**
NAS-Bench-201's own maintainers mark it deprecated in favor of NATS-Bench, which has the same tabular-lookup, zero-training-compute property (15,625 architectures × CIFAR-10/100/ImageNet-16-120) but is faster and more actively maintained. Verified via the actual upstream repo status, not assumed.

**Left `naslib` out of the locked dependency set rather than force a resolution.**
It has no PyPI release (last upstream push 2024-11-11) and its git-source install currently fails outright — `git submodule update --init` errors on a broken reference (`sphinx_source_code` has no URL in `.gitmodules`), with no known upstream fix found in a real search. Forcing `uv lock` to include it would have left the entire project's lockfile unbuildable over one broken dependency. `nats-bench` (which does resolve cleanly) stayed in; `naslib` is documented inline in `pyproject.toml` as a known, unresolved blocker — the actual first task for implementing `plugins/nas_search/`, not a documentation gap to paper over.

**Fixed three real, independently-verified bugs in `docker/Dockerfile` and CI rather than assume the pivot's own changes were clean.**
(1) The builder stage's editable install recorded a path reference to `/build`, which doesn't exist in the runtime stage after `COPY --from=builder ... /build /app` — fixed with `--no-editable`. (2) `ENTRYPOINT ["sde"]` meant `docker compose run --rm api pytest tests/ -v` actually executed `sde pytest tests/ -v`, not a real pytest invocation — fixed with an explicit `--entrypoint pytest` override in CI and the README. (3) `--no-dev` meant pytest itself was never installed in the image at all, despite `docker compose run --rm api pytest ...` being documented as the intended workflow — fixed by switching to `--extra dev`. All three were confirmed pre-existing (reproduced on a main commit dated before this pivot session started) rather than assumed to be regressions, and all three were confirmed fixed against a live GitHub Actions run, not just reasoned about locally.

**Removed the `ecc` plugin/marketplace; adopted [skills.sh](https://www.skills.sh/) as the project's skill-finder.**
Explicit user preference. `ecc` was project-scoped (`.claude/settings.json`, not global), so removal doesn't affect other projects. Two Phase-2 skill picks (`python-testing-patterns`, `python-best-practices`) were re-sourced from skills.sh instead, each checked for active maintenance (commit recency, star count) before installing, not installed on trust alone.
